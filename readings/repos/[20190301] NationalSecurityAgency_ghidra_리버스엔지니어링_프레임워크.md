## 한 줄 요약

소스 없는 실행 파일을 열어 기계어 → 어셈블리 → C 비슷한 코드로 되돌리고, 호출 관계를 그래프로 보여 주는 리버스 엔지니어링 도구다. 유료 IDA Pro의 무료 대안으로 가장 많이 쓰이고, REA 같은 에이전트 도구도 무료 분석 엔진으로 Ghidra를 붙인다.

## 기능 범위

| 영역 | 내용 |
|---|---|
| 디스어셈블·디컴파일 | 기계어를 어셈블리와 C 비슷한 코드로 복원한다. 디컴파일러 본체는 C++(`Features/Decompiler/src/decompile/cpp`, 소스 231개)로 따로 돈다 |
| 지원 CPU | `Ghidra/Processors/` 아래 39종 (x86, ARM, AARCH64, MIPS, RISC-V, PowerPC, Dalvik, JVM, eBPF 등) |
| 실행 파일 형식 | PE, ELF, Mach-O 등 (`FileFormats`), PDB 심볼, Objective-C, Swift, Rust, Go(`GhidraGo`) 보조 분석 |
| 그래프 | 함수 내부 흐름(`FunctionGraph`), 함수 호출 관계(`GraphFunctionCalls`) |
| 함수 유사도 검색 | BSim (아래 절) |
| 버전 비교 | `VersionTracking`, `ProgramDiff`, `CodeCompare`. 같은 프로그램의 두 버전에서 바뀐 함수를 찾고 분석 결과(이름, 주석)를 옮긴다 |
| 디버거 | gdb, lldb, WinDbg(dbgeng), x64dbg 등에 붙는 에이전트(`Ghidra/Debug/`) |
| 에뮬레이션 | `SystemEmulation`으로 코드를 실제 CPU 없이 돌려 본다 |
| 협업 | `GhidraServer`로 여러 분석가가 같은 저장소를 공유한다 |
| 자동화 | 화면 없이 도는 헤드리스 모드, Java·Python(PyGhidra) 스크립트와 확장 |

## 핵심 구조: 명세 언어와 중간 표현

```
기계어 바이트
   │  SLEIGH 명세 (CPU마다 .slaspec 파일, 저장소에 150개)
   ▼
P-code  ── CPU와 무관한 중간 표현 (레지스터 전송 언어)
   │
   ├─▶ 디컴파일러 (C++) ─▶ C 비슷한 코드
   ├─▶ 에뮬레이터
   └─▶ BSim 특징 추출 ─▶ 유사 함수 검색
```

- **SLEIGH**: CPU 명령어가 무엇을 하는지 적는 명세 언어다. 새 CPU를 지원하려면 디컴파일러를 고치지 않고 SLEIGH 명세만 새로 쓴다.
- **P-code**: 모든 CPU 명령을 같은 작은 연산 집합으로 바꾼 중간 표현이다. 디컴파일, 에뮬레이션, 유사도 분석이 전부 이 위에서 돈다. 그래서 기능 하나를 만들면 39종 CPU에 한 번에 적용된다.

## BSim: 컴파일 차이에 강한 함수 유사도 검색

공식 도움말(`BSim/BSimOverview.html`) 기준이다.

- 이미 분석한 실행 파일의 함수 정보를 DB에 쌓아 두고, 새로 받은 바이너리의 함수와 **비슷한 함수를 찾는다.** 이미 본 라이브러리나 함수를 빨리 알아보는 용도다.
- 특징은 기계어 바이트가 아니라 디컴파일러가 만든 **데이터 흐름 그래프(P-code 기반)**에서 뽑는다. 같은 뜻의 다른 명령, 레지스터·스택 배치, 명령 순서, 여러 컴파일러 변형, 일부 난독화의 차이를 정규화한다.
- 색인은 텍스트 검색 방식으로 만들어 최근접 이웃 검색을 한다. 특징이 전부 같지 않아도 설정한 비율만 맞으면 찾는다. 소스가 조금 바뀐 함수도 찾을 수 있다.
- 도움말은 함수 수백만 개 DB에서도 질의 1건이 마이크로초 단위로 끝난다고 적는다(측정 조건은 적혀 있지 않음, 미검증).
- 저장소는 PostgreSQL(BSim 전용 확장 필요), Elasticsearch(클러스터 분산), H2(개인용 로컬 파일) 세 가지다.

## 한계와 주의

- **보안 취약점 경고.** README가 일부 버전에 알려진 취약점이 있다고 경고한다. 의심스러운 바이너리를 열기 전에 보안 권고를 확인하고 최신판을 쓴다.
- **설치가 무겁다.** JDK 25가 필요하고, 소스 빌드는 Gradle 9.1+, Python 3.9~3.15, C/C++ 컴파일러까지 요구한다. 보통은 릴리스 zip(또는 `brew install --cask ghidra`)을 쓴다.
- **디컴파일 결과는 원래 소스가 아니다.** 변수 이름, 타입, 구조체는 분석가가 채워야 읽을 만해진다. 에이전트가 이 결과를 그대로 원본처럼 다루면 틀린 결론을 낸다.
- **BSim은 따로 구축해야 한다.** 쓰려면 함수 DB를 먼저 쌓아야 하고, PostgreSQL은 전용 확장을 빌드해야 한다.
- **라이선스는 무료지만 분석 대상의 약관은 별개다.** 남의 소프트웨어를 분석할 때 그 소프트웨어의 라이선스와 관할 법을 따로 확인해야 한다.

## 가져올 수 있는 부분

| 대상 | 가져올 수 있는 부분 |
|---|---|
| 에이전트 도구 설계 | 앞단(SLEIGH 명세)과 뒷단(디컴파일러, 에뮬레이터, BSim)을 P-code 하나로 분리하는 구조. 데이터 소스가 늘어도 공통 중간 표현 하나에만 맞추면 뒷단 기능을 그대로 재사용한다 |
| 유사도 검색 | 원본 표면(기계어 바이트) 대신 **정규화한 구조(데이터 흐름 그래프)**에서 특징을 뽑아 표현 차이를 지우는 방식. 표현은 달라도 같은 구조인 대상을 묶을 때 그대로 적용된다 |
| 검색 저장소 선택 | 같은 기능을 PostgreSQL, Elasticsearch, H2 세 저장소로 제공해 규모에 맞게 고르는 방식 |
| 버전 비교 | 두 버전 사이에 바뀐 함수만 찾고, 이전 분석 결과(이름, 주석)를 새 버전으로 옮기는 Version Tracking 흐름 |
| 에이전트 연동 | 헤드리스 모드와 PyGhidra가 있어 MCP 서버 뒤에 붙이기 쉽다. REA가 이 경로를 쓴다 |
