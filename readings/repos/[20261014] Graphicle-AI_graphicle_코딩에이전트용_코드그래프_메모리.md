# Graphicle: 코딩 에이전트용 코드 그래프와 프로젝트 메모리를 한 프로그램으로

- **레포**: [Graphicle-AI/graphicle](https://github.com/Graphicle-AI/graphicle) · [벤치마크 문서](https://github.com/Graphicle-AI/graphicle/blob/main/docs/benchmarks.md)
- **제작**: KarLex AI (기여자 3명, 익명 포함 · 2026-10-19 기준)
- **공개**: 2026-10-14 저장소 생성일 (Rust, Apache-2.0, 별 297개 · 2026-10-19 GitHub API 기준)
- **읽은 날짜**: 2026-10-19 (커밋 `160fb92`, 릴리즈 `v0.1.2`)
- **원형**: 코드 그래프 엔진은 [Graphify](https://github.com/Graphify-Labs/graphify)(Python)의 Rust 이식판이고, 메모리·앱·세션 수집은 자체 구현
- **태그**: #CodeGraph #AgentMemory #MCP #ClaudeCode #treesitter #Benchmark #LocalFirst

## 한 줄 요약

저장소를 코드 그래프(파일, 함수, 클래스, 호출, import)로 만들고, 문서·결정 사항·지난 에이전트 세션을 **프로젝트 메모리**로 쌓아, 코딩 에이전트에게 **파일과 줄 번호가 붙은 발췌**를 토큰 예산 안에서 돌려주는 로컬 도구다. 그래프, 메모리, MCP 서버, 웹 앱이 Rust 프로그램 하나와 SQLite 파일 하나에 들어 있다. 눈여겨볼 것은 기능보다 **벤치마크를 쓰는 태도**다. 자기 도구가 grep과 비긴다고 적는다.

## 기능

| 기능 | 내용 |
|---|---|
| 코드 그래프 | tree-sitter로 파일, 함수, 클래스, 호출, import를 파싱(모델 호출 없음). 심볼 설명, 경로 추적, 영향 범위(`graph affected "retry()"`), HTML 그래프 내보내기 |
| 프로젝트 메모리 | 문서(Markdown, PDF, Office, HTML), 검토한 결정·절차, 지난 Claude Code·Codex 세션을 코드와 함께 검색 |
| 예산 안의 근거 발췌 | `graphicle context`와 MCP 도구가 출처가 붙은 발췌를 토큰 예산 안에서 반환. 이 단계는 모델을 부르지 않고 에이전트의 모델이 읽는다 |
| MCP 서버 | 코드 그래프 도구는 Graphify의 도구 이름(`query_graph`, `get_neighbors`, `shortest_path`)을 그대로 쓰고, 메모리 도구를 함께 제공. `--pull-requests`로 PR 영향 분석 도구 추가 |
| 세션 수집 | 에이전트 세션의 끝난 턴을 저장하고, 새 세션을 검토된 메모리와 최근 턴으로 시작 |
| 웹 앱 | `graphicle open`으로 그래프, 원천, 메모리를 보고 **에이전트가 제안한 메모리를 승인** |
| 설치·해제 | `graphicle setup`이 저장소 색인, 에이전트 연결, Git 훅 설치, `AGENTS.md` 두 줄 추가. 바꾼 파일을 모두 백업하고 `graphicle disconnect`로 되돌림 |

모델 없이 대부분 동작한다. `ask`의 문장 답변, 메모리 제안, 문서·이미지 해석에만 모델이 필요하고 Ollama나 OpenAI 호환 서버도 쓸 수 있다.

## 메모리를 코드 심볼에 묶는 규칙

`crates/graphicle/README.md`의 "Memory anchored to code symbols" 절 기준이다.

- 검토된 메모리가 코드 파일의 일부를 인용하면, 그 인용을 감싸는 **심볼(함수, 클래스, 메서드)에 연결**한다. 심볼 id, 리비전, 경로, 정규 이름을 함께 둔다.
- 메모리는 **파일 단위가 아니라 심볼 단위로 낡는다.** 연결된 심볼의 줄(시작부터 다음 정의 전까지)이 바뀌면 메모리를 내보내지 않는다(`symbol_changed`, 심볼이 사라지면 `symbol_missing`). 같은 파일의 다른 곳이 바뀌면 메모리는 그대로 유효하다.
- 내용이 같은 파일의 이동·이름 변경은 따라간다. 그래프가 다시 만들어지는 동안에는 바뀐 파일의 메모리를 보류한다(`projection_pending`).
- 심볼 밖의 인용, 여러 심볼에 걸친 인용, 코드가 아닌 파일은 파일 단위 규칙을 쓴다.

README는 커밋 30개 뒤에 메모 30개를 표본 조사해, 함수가 바뀐 15개만 낡음으로 표시했다고 적는다. 더 넓은 탐색 점검에서는 잘못 표시된 경우가 일부 있었다고 함께 밝힌다.

## 개인정보와 로컬 동작

- 데이터는 SQLite 하나에 모인다(macOS는 `~/Library/Application Support/Graphicle`). 앱과 HTTP·MCP는 127.0.0.1에서만 연다.
- 동기화는 `.gitignore`를 따르고 `.env`, 키, 자격 증명 파일을 건너뛴다. 세션 수집은 자격 증명을 가린다.
- 네트워크는 설정한 모델·커넥터, 전체 그래프 추출(문서·이미지를 찾은 API 키의 LLM에 보냄), GitHub CLI 작업, 하루 한 번 새 버전 확인에만 쓴다. 버전 확인은 기본으로 켜져 있고 `GRAPHICLE_NO_UPDATE_NOTIFIER=1`로 끈다.
- **삭제 영수증**: 메모리나 세션을 지우면 그것에서 파생된 것까지 지우고, 해시 체인으로 묶인 삭제 영수증을 준다.

## 벤치마크

`docs/benchmarks.md` 기준이다. 에이전트 실험에서는 95% 신뢰구간이 0을 포함하면 차이를 인정하지 않고 "비김"으로 적는다.

| 항목 | 결과 (문서 기재값) |
|---|---|
| 속도 (Graphify 0.9.91 대비) | 코드베이스 13개 × 작업 3종 = 39번 측정 모두에서 3.0~22.7배 빠름. 단, 두 그래프의 노드 수가 최대 4.7%, 엣지 수가 최대 2.0% 다르다 |
| 최대 메모리 | 39번 모두 Graphify보다 적음 (0.29~0.97배) |
| 증분 갱신 | 커밋 30개 뒤 `graph update`가 6~8배 빠르고 새로 만든 그래프와 일치 |
| 코드 찾기 (SWE-bench Verified 100개, Claude Code + Opus 5.5) | 수정된 파일을 모두 찾은 과제: Claude Code만 95, Graphicle 95, Graphify 94. **grep과 비김.** 토큰은 Graphicle이 16%, Graphify가 29% 더 씀. 에이전트가 Graphicle 도구를 **한 번도 부르지 않았다** |
| 질문 답하기 (Graphify 예시 코퍼스 30문항) | 사실 포함률: Graphicle 99.2%, Claude Code만 94.7%(비김), Graphify 87.8% |
| 에이전트 메모리 (메모리 시스템 7종과 비교) | 개발 세트 3개(LoCoMo-10, LME-84, BEAM-100K)에서 어느 시스템에도 뒤지지 않음. LoCoMo-10 87.66점으로 Hindsight(87.27)와 비김, Mem0(81.88), MemMachine, Honcho, Cognee, Graphiti, Mastra보다 높음 |

메모리 비교는 실험 방식이 눈에 띈다.
- 점수를 매기기 전에 **비교 21개와 판정 규칙을 미리 등록**하고, Holm 보정을 한 p값과 신뢰구간이 모두 조건을 넘을 때만 "이김"이라고 쓴다.
- 모든 시스템에 같은 오픈 모델을 답변자와 채점자로 쓰고, 프롬프트 경로 두 개와 강한 답변자로 다시 확인한다.
- 시스템마다 적재 단계의 LLM 호출 수와 토큰을 함께 적는다. LoCoMo 대화 하나당 Graphicle 12.2회, Mem0 332회, Graphiti 1,362.6회다.
- 스스로 붙인 단서: 개발 세트 결과이고, 평가에 쓴 렌더러(`render_v2.py`)는 배포판에 없으며, 컨텍스트 구성을 같은 답변자·채점자로 LoCoMo-10에서 골랐다. 보류 세트로 확인하기 전에는 대표 주장으로 쓰지 않는다고 적는다.

## 한계와 주의

- **아직 0.1.x다.** 저장소가 생긴 지 5일 됐고 기여자는 3명이다. 0.1.0 → 0.1.2가 나흘 사이에 나왔다.
- **에이전트가 도구를 안 쓴다.** SWE-bench 실험에서 Claude Code가 Graphicle 도구를 한 번도 부르지 않았다. 설치만 한다고 효과가 생기지 않고, 언제 부를지 지침이나 훅이 따로 필요하다.
- **코드 찾기는 grep과 비긴다.** 토큰 절감도 주장하지 않는다고 README에 적혀 있다.
- **메모리 점수는 출시판 기준이 아니다.** 배포하지 않은 렌더러를 쓴 사전 빌드의 개발 세트 결과다. 긴 세션과 여러 세션에 걸친 메모리는 아직 시험하지 않았다.
- **`setup`이 여러 설정 파일을 고친다.** `.mcp.json`, `.claude/settings.local.json`, `~/.codex/config.toml`, `AGENTS.md`, Git 훅을 바꾼다. 백업과 `disconnect`가 있지만, 사내 저장소에 쓰기 전에 바뀌는 파일 목록을 확인해야 한다.
- **전체 그래프 추출은 문서를 외부 LLM으로 보낼 수 있다.** 찾은 API 키의 모델로 문서·이미지를 보낸다. 사내 코드에는 `--code-only`를 쓰는 편이 안전하다.
- Windows판은 코드 서명이 안 된 미리보기다.

## 가져올 수 있는 부분

| 대상 | 가져올 수 있는 부분 |
|---|---|
| 평가 보고 방식 | 비교와 판정 규칙을 미리 등록하고, 신뢰구간이 0을 포함하면 "비김"으로 적고, 개발 세트와 보류 세트 결과를 구분하는 방식. **자기 도구가 grep과 비겼다, 에이전트가 도구를 안 불렀다**까지 적는 보고 태도는 RAG·에이전트 평가 문서에 그대로 가져올 만하다 |
| 비용을 함께 적는 비교 | 정확도 옆에 적재 단계 LLM 호출 수와 토큰을 나란히 두는 표. 비슷한 점수라도 호출이 10~100배 차이 나는 것이 드러난다 |
| 메모리 무효화 | 메모리를 원천의 **가장 작은 단위(심볼)**에 묶고, 그 단위가 바뀔 때만 낡음으로 표시하는 규칙. 문서 기반 RAG에서도 청크를 절·조항 단위에 묶어 그 절이 바뀔 때만 다시 만드는 식으로 응용할 수 있다 |
| 메모리 쓰기 관리 | 에이전트가 제안한 메모리는 사람이 승인해야 반영되고, 삭제하면 파생물까지 지우고 영수증을 남긴다 |
| 근거 발췌 응답 | 모델을 부르지 않고 파일·줄 번호가 붙은 발췌를 토큰 예산 안에서만 돌려주고, 해석은 호출한 에이전트의 모델에 맡기는 MCP 도구 설계 |
| 설치 도구 설계 | 바꾸는 파일을 모두 나열하고 백업한 뒤, 명령 하나(`disconnect`)로 전부 되돌리는 설치 방식 |
| 도구 사용 유도 | 좋은 도구도 에이전트가 부르지 않으면 효과가 없다는 측정 결과. MCP 도구를 붙일 때 호출 시점을 지침·훅으로 따로 설계해야 한다 |
